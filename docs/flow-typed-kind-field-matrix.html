FLOW 类型、参数与映射依赖清单

V1.4 · 2026-09-11 · 分支 codex/v1.4-source-baseline · 当前源码核查

建议：先统一现有普通 TRIM / VERIFY 的新增与编辑字段规则，再扩充专用类型。已有 typed kind 可以作为规则入口，但必填和资源约束分布在各领域编译器；注册表本身不是字段字典。本文是整理结果和实施建议，未改变程序行为。

目前支持类型依赖表共同关联已发现缺口实施顺序

1. 当前入口的真实支持范围

入口已经具备尚需补齐
新增测试项普通 FBIST STANDARD_TRIM / STANDARD_VERIFY；Pattern、存储候选、参数、插入位置、一次写入草稿。专用 kind 仅识别并提示，prepare 明确拒绝其他类型；不是所有 TYPE 都能新增。
编辑测试项弹窗按当前行回填全部实际列，保留原值及 Recipe；保存变化字段、一次撤销。表格编辑仍保留。当前只是按固定列分区，未按 kind 调整字段。TRIM 有流程映射按钮，TRIM/VERIFY 有存储映射按钮；映射单独保存、单独撤销。多行项仍逐行编辑。
生产编译先分类，再生成领域计划，最后注册表分派平台组装。当前原生注册表有 24 个 kind。“分类器能识别”不等于“有原生注册”或“所有模式都能编译”。固件行分类与最终测试项分类还不同。

依据：flow_new_item.py · handle_flow_new_item 附近的 supported/prepare 门禁；index.html · renderFlowItemEdit / saveFlowItemEdit；flow_input.py · describe_flow_input；registered_typed_kinds.py · NATIVE_TYPED_KIND_REGISTRY。

2. 类型 → 参数 → 资源依赖

共同身份字段为 CP / item / type / mode。下表“必需”指已核实的该路径要求；“条件”由模式、Recipe、资源或分组决定；未列出的列不能据此自动删除。专用类型均尚未接入新增向导。可按类型或资源名称筛选：

STANDARD_TRIM
trim；排除 Pdr_Trim / Bor_Trim；新增限定 fbist		DAC bit 为正整数且不超过动态字段宽度；Bisection 为 yes/no/both/both_m。step 空或 / 表示完整码域，否则为自定义码序，不能重复。target 数值；单位按编译分支筛选。当前向导还要求引脚、供电、上下限、电气激励，频率激励可 /。ENTER 进入 Pattern + TRIM 动态 DAC Pattern；DAC 动态字段唯一。可有 RUN、DEPEND。存储宽度取搜索位数与动态字段宽度较大者，另受 OTP/UID/PUMP 和后续节点约束。已支持新增。统一“完整/自定义码序”联动 LINE 与 step；选择 DAC 后显示位宽。

freq_test
PVD_TEST

pvd_test

3. 应统一的字段与关联规则

触发条件应显示/检查不能默认推断
选择/改变 type、mode、item、FV/FI、Recipe重新调用现有分类器；再按对应领域契约显示必填、条件、来源、禁止字段。同一个 type 永远对应同一表单；分类可接受的 mode 一定能编译。
普通 TRIM 选择 DAC Pattern唯一动态字段、宽度、搜索位数、码序；完整码域写 LINE=yes/step=/，自定义写 LINE=no。DAC bit 必须等于字段宽度；所有自定义码必须小于 2^DACbit（生产按字段宽度检查）。
普通测量填写 UNIT/target新增时可按现有约定给激励、上下限建议；标明来源与是否手改。编辑已有项只在明确联动后更新其他值。所有 kind 的 target 都是测量目标；所有 kind 都能用 target±1%；所有全表单位都适用。
OTP/UID=yes有效 ADDR_MAP、位宽、占用、CP、页、后续 BUILDMAP/COMMIT；VERIFY 还需 EXPORT 编码（当前向导 BCD16_MV/ADC12_3V3）。选了地址就完成烧写；OTP 与 UID 是同一种页过滤规则；type=uid 等于 UID=yes。
PUMP=yes动态 PUMP 资源、非空存储绑定、同 CP 后续 SETVPOSP；当前按 item 聚合的资源关系。普通 TRIM 选中别名 DAC 后 PUMP 自动具备；关闭 OTP 就无需存储。
无持久化需求普通 TRIM 显式“仅运行时结果、不存储”；展示已有跨 CP 同逻辑项全局映射并沿用。标志全 no 等于可静默清空共享映射。
PE=erase/program适用 kind 和 NM_pattern 对应用途；专用 PDR_VERIFY 明确禁止。PE 是任何 TYPE 都能开的通用开关。
多行项、DEPEND 或存储节点组连续性、bins/供电共享约束、生产者在前消费者在后；改名和插入位置预览影响。逐行保存等于整项编辑；移到任意位置都有效。

核心依据：新增局部校验与位置检查、project_mappings、result_binding、trim_use_def、memory_wakeup。本轮存储规则主要复核新增入口，完整存储协议沿用既有领域实现，不扩展为所有专用 kind 均可导出。

4. 扩充前应处理的具体缺口

  1. 新增与编辑未共用字段描述。新增读取 describe_flow_input，编辑按固定列分组；切换类型会保留可能不适用的原值，当前依赖之后整本检查发现。
  2. 全表枚举过宽。schema 提供 mV，但普通 TRIM 的 _compile_measurement 电压分支只接受 V；普通 VERIFY 频率 gate 的缩放表仅有 Hz/kHz/MHz，而全表含 GHz。应按实际消费者收窄选项或先完善消费者，不能只凭枚举开放。
  3. 普通 VERIFY 的条件必填还不完整。当前字段描述把 target/上下限整体标为可选；生产会根据 VERSION 来源决定限值，并在频率分支直接读取 target。表单应给出真实来源和缺项，不能把 optional 理解为可无条件省略。
  4. 识别范围、枚举范围、原生支持范围存在差异。adjust 缺 TYPE 枚举；FREQ/DC 的领域模式限制比分类器更窄；部分分类结果没有同名原生注册。需要逐类确认，禁止仅增加下拉值。
  5. 专表和阶段需要单独的交互。OPA/DAC 读取专表有效用例，ADC/DC/固件可能多行；先做一套按实际资源展示来源和跳转的界面，再考虑变更组结构。

以上是源码检查结果或明确标注的待验证点；本次没有修复这些缺口，也没有修改母本或交付包。

5. 推荐实施顺序与验收口径

阶段工作范围完成标准
下一步：普通路径对齐让现有编辑弹窗也调用 flow_input；按普通 TRIM/VERIFY 应用字段和单位范围、限值来源、Pattern/ADDR_MAP 缺项提示。保留原值和表格入口。同一数据新增/编辑识别一致；选类型后预览不适用旧值，未经确认不清除；取消无变化；单项修改/撤销、另存重开、完整编译通过。复杂 Recipe 保留高级入口。
首批专用扩充建议 OS、FREQ_TEST，然后 PDR_TRIM/PDR_VERIFY。先使用现有资源，不同时重做专表编辑器。每类具备明确可用模式、字段、资源入口和缺项定位；创建→编辑→保存重开→生成验证。PDR 固定规则有针对性测试。
专表驱动类型OPA、DAC、PVD；显示专表来源并跳转配置，防止通用默认值污染。不适用字段明确处理；专表修改后重读依赖；旧项原值不被自动覆盖。
多行及强顺序类型ADC、DC、固件整组编辑；其后 UID/ID、读写、Flash/VT/Margin/MAIN。同步评估参数和映射一次事务。组连续性、bins/供电、改名影响、生产者/消费者顺序可视且校验；整组创建/编辑/撤销一致。
待审计分支BOR、独立 SHMOO、通用 SWD/SCAN/MBIST/COMP、DAC_ADJUST 的入口契约。先确认现有最终编译路径和支持边界，再决定开放、迁移或继续限制。

排序为工程建议，依据是现有规则完整度、单行/多行依赖和验证成本，未依据用户使用频率作统计。建议先完成第一阶段，不一次扩充全部类型。

6. 核查范围

使用当前 V1.4 本地源码定向读取：分类器、24 项原生注册、现有新增/编辑入口，以及上表链接的领域路径。Codebase Memory 工具本轮未暴露，使用本地源码回退。范围包含明确读取的当前文件（包括既有未提交工作），未做全仓库、历史包、生成产物、所有旧平台路径或所有模式组合的穷尽审计。

“无注册”只针对当前 NATIVE_TYPED_KIND_REGISTRY 的显式 24 项；不宣称项目没有其他实现。MAIN、DAC_ADJUST 及待审计分支的完整字段规则仍待深入核查。文档链接和既有字段描述测试另行检查；不代表新功能已实现或厂商编译已通过。
