01 / 工具作用

让测试工程师围绕测试意图工作

工具把测试参数、执行顺序、数据依赖和资源配置转译为平台程序，减少反复填写代码、对齐名称和手动拼接资源的工作。工程师仍负责确定测试方法、电气条件与验收标准，工作台负责将这些已定义的规则一致地落实到输出中。

01 · INPUT载入与编辑

读取 Excel 母本，按 CP、测试项或资源分区填写配置。

02 · RECIPE编排测试步骤

逐模块编辑 Recipe，拖动调整测试项或模块顺序。

03 · CHECK检查并修正

查看字段错误和跨表问题，定位来源，修改后复查。

04 · PREVIEW审阅实际代码

自动查看当前项函数；检查通过后预览整份输出。

05 · OUTPUT生成与留档

按目标输出程序或资源，记录输入快照、文件清单与结果。

典型场景：修改一个 TRIM 项的目标值或 Recipe，自动查看对应函数变化；检查配置后选择平台与 CP，再生成程序查看版。填写尚未完成时，也可以先另存 Excel 草稿，下一次继续。

02 / 现有功能

从表格编辑，走到完整工作流程

01 · 配置工作台

保留熟悉的表格操作

支持单格与区域选择、复制粘贴、清空、向下填充、批量填写、撤销与重做；可调整行高列宽，并按 CP 等实际字段分区浏览。

作用：集中处理配置，减少在大表中查找和重复输入。

02 · 测试项管理

新增、整项复制与排序

FLOW 可追加空白行、复制既有行或完整测试项。同 CP 内拖动整项时，连续 sub 与参数共同移动；顺序会进入保存结果和执行计划。

作用：复用已有测试结构，降低漏复制子步骤的风险。

03 · Recipe 编排

按模块理解和调整流程

独立编辑页支持模块增删、参数填写和拖动排序，提供分类帮助、格式示例与语法提示。默认流程以灰字展示，实际应用后才进入草稿。

作用：把长串流程表达拆成可逐步核对的操作。

04 · 填写辅助

说明、下拉与诊断就近呈现

参考母本 15 张表的 152 个有名称字段均有说明；固定枚举字段提供下拉。检查问题可跳到表、行或单元格，并展开对应隐藏列。

作用：帮助理解字段含义，让配置问题更容易找到来源。

05 · 代码透明

边配置，边看生成结果

选中 FLOW 项自动预览实际函数，参数与已应用 Recipe 改动后自动更新；支持 Chroma / S100 切换，桌面版可打开独立代码窗口。

作用：在输出文件之前，审阅配置对代码的实际影响。

06 · 保存与输出

把草稿、检查与生成连起来

支持未验证草稿另存、检查结果另存、窗口草稿暂存与恢复；生成区显示准备条件、目标和目录，结果按目标汇总成功或失败并提供文件查看。

作用：保留阶段成果，明确当前版本是否已保存、已检查。

Vref0P8_Abs_Trim()
{
  TEST_NUM=150;
  TEST_NO(TEST_NUM);DATALOG_MSG="Vref0P8_Abs_Trim";
  TEST_NO(TEST_NUM);DATALOG_MSG="vref0p8_abs_trim";

  double trimTar=0.8;

  double trimValue[MAX_SITE],trimFinalValue[MAX_SITE];
  int trimDac[MAX_SITE];

  int dacArray[15]={8,9,10,11,12,13,14,15,0,1,2,3,4,5,6};
  int dacIndex[MAX_SITE];
  int firstIndex=sizeof(dacArray)/sizeof(dacArray[0])/2;
  int binAryCyc=2;

  //initial
  for(I=0;I<MAX_SITE;I++)
  {
    trimValue[I]=0;
    trimFinalValue[I]=0;

    trimDac[I]=dacArray[firstIndex];
    dacIndex[I]=firstIndex;

  }

  POWER_ON(VCC_TYP);

  RELAY_ON(TP,PPMU_PDCL,2mS);

  TEST_NUM++;
  TEST_NO(TEST_NUM); DATALOG_MSG="enter_fbist_mode";
  JUDGE_PAT(enter_fbist_mode,__enter_fbist_mode);

  TEST_NUM++;
  TEST_NO(TEST_NUM); DATALOG_MSG="enter_vref0p8_abs";
  JUDGE_PAT(enter_vref0p8_abs,__enter_vref0p8_abs);

  TEST_NUM++;
  TEST_NO(TEST_NUM); DATALOG_MSG="set_iref1u_dac";
  JUDGE_PAT(set_iref1u_dac,__set_iref1u_dac);

  FORCE_I_PPMU(TP, 0uA, @2uA, ,6V, -2V ,3mS);
  do
  {
    set_vref0p8_abs_trim_data(trimDac);

    MEAS_V_PPMU(TP, 2mS, 16, AVE, 50uS);
    TEST_NUM++;
    TEST_NO(TEST_NUM);DATALOG_MSG="vref0p8_abs_trim";
    SOCKET_INC(FRZ_OFF)
    {
      trimValue[SOCKET] = RESULT_PIN(SOCKET, TP);
      JUDGE_VARIABLE(SOCKET,trimDac[SOCKET], 0, 15, "Vref0p8_ABS_dac");
      JUDGE_VARIABLE(SOCKET,trimValue[SOCKET], -0.8, 4.8, "Vref0p8_ABS_value");

      if(fabs(trimValue[SOCKET]-trimTar)<fabs(trimFinalValue[SOCKET]-trimTar))
      {
        trimFinalValue[SOCKET] = trimValue[SOCKET];
        VREF0P8_ABS_DAC_FINAL[SOCKET] = trimDac[SOCKET];
      }

      if (trimValue[SOCKET] < trimTar)
      {
        dacIndex[SOCKET] = dacIndex[SOCKET] + (int)pow((float)2, (float)binAryCyc);
        trimDac[SOCKET] = dacArray[dacIndex[SOCKET]];
      }

      else
      {
        dacIndex[SOCKET] = dacIndex[SOCKET] - (int)pow((float)2, (float)binAryCyc);
        trimDac[SOCKET] = dacArray[dacIndex[SOCKET]];
      }

    }

    binAryCyc-=1;

  }while(binAryCyc>=-1);
  //fflush(stdout);

  set_vref0p8_abs_trim_data(VREF0P8_ABS_DAC_FINAL);

  TEST_NUM++;
  TEST_NO(TEST_NUM); DATALOG_MSG="vref0p8_abs_trim";

  SOCKET_INC(FRZ_OFF)
  {
    JUDGE_VARIABLE(SOCKET,VREF0P8_ABS_DAC_FINAL[SOCKET],0, 15, "Vref0p8_ABS_dac_f");
  }

  FORCE_I_PPMU(TP, 0uA, @2uA, ,6V, -2V ,3mS);
  DATALOG_MSG="Vref0p8_ABS_value_f";
  JUDGE_V_PPMU(TP, 0.793V, 0.807V, 2mS,16,AVE,50uS,,);
  TEST_NUM++;
  TEST_NO(TEST_NUM); DATALOG_MSG="exit_fbist_mode";
  JUDGE_PAT(exit_fbist_mode,__exit_fbist_mode);

  RELAY_OFF(TP, PPMU_PDCL, 2mS);
  POWER_OFF();
  //POWER_DOWN_FAIL_SITE_X(MODE_B);

}


Vref0P8_Abs_Dac_Loop()
{
  TEST_NUM=150;
  TEST_NO(TEST_NUM);DATALOG_MSG="Vref0P8_Abs_Dac_Loop";
  TEST_NO(TEST_NUM);DATALOG_MSG="vref0p8_abs_dac_loop";

  double trimTar=0.8;

  double trimValue[MAX_SITE],trimFinalValue[MAX_SITE];
  int trimDac[MAX_SITE];

  int cyc=0;
  int endCyc=16;
  char cycMsg[48];

  //initial
  for(I=0;I<MAX_SITE;I++)
  {
    trimValue[I]=0;
    trimFinalValue[I]=0;

    trimDac[I]=0;

  }

  POWER_ON(VCC_TYP);

  RELAY_ON(TP,PPMU_PDCL,2mS);

  TEST_NUM++;
  TEST_NO(TEST_NUM); DATALOG_MSG="enter_fbist_mode";
  JUDGE_PAT(enter_fbist_mode,__enter_fbist_mode);

  TEST_NUM++;
  TEST_NO(TEST_NUM); DATALOG_MSG="enter_vref0p8_abs";
  JUDGE_PAT(enter_vref0p8_abs,__enter_vref0p8_abs);

  TEST_NUM++;
  TEST_NO(TEST_NUM); DATALOG_MSG="set_iref1u_dac";
  JUDGE_PAT(set_iref1u_dac,__set_iref1u_dac);

  FORCE_I_PPMU(TP, 0uA, @2uA, ,6V, -2V ,3mS);
  do
  {
    sprintf(cycMsg,"vref0p8_abs_trim_dac_%d",cyc);
    cyc++;
    set_vref0p8_abs_trim_data(trimDac);

    MEAS_V_PPMU(TP, 2mS, 16, AVE, 50uS);
    TEST_NUM++;
    TEST_NO(TEST_NUM);DATALOG_MSG="vref0p8_abs_trim";
    SOCKET_INC(FRZ_OFF)
    {
      trimValue[SOCKET] = RESULT_PIN(SOCKET, TP);
      JUDGE_VARIABLE(SOCKET,trimValue[SOCKET], -0.8, 4.8, cycMsg);

      if(fabs(trimValue[SOCKET]-trimTar)<fabs(trimFinalValue[SOCKET]-trimTar))
      {
        trimFinalValue[SOCKET] = trimValue[SOCKET];
        VREF0P8_ABS_DAC_FINAL[SOCKET] = trimDac[SOCKET];
      }

      if(cyc<endCyc) trimDac[SOCKET] = cyc;
    }

  }while(cyc<endCyc);
  //fflush(stdout);

  set_vref0p8_abs_trim_data(VREF0P8_ABS_DAC_FINAL);

  TEST_NUM++;
  TEST_NO(TEST_NUM); DATALOG_MSG="vref0p8_abs_trim";

  SOCKET_INC(FRZ_OFF)
  {
    JUDGE_VARIABLE(SOCKET,VREF0P8_ABS_DAC_FINAL[SOCKET],0, 15, "Vref0p8_ABS_dac_f");
  }

  FORCE_I_PPMU(TP, 0uA, @2uA, ,6V, -2V ,3mS);
  DATALOG_MSG="Vref0p8_ABS_value_f";
  JUDGE_V_PPMU(TP, 0.793V, 0.807V, 2mS,16,AVE,50uS,,);
  TEST_NUM++;
  TEST_NO(TEST_NUM); DATALOG_MSG="exit_fbist_mode";
  JUDGE_PAT(exit_fbist_mode,__exit_fbist_mode);

  RELAY_OFF(TP, PPMU_PDCL, 2mS);
  POWER_OFF();
  //POWER_DOWN_FAIL_SITE_X(MODE_B);

}

03 / 输出能力

既能生成程序，也能单独准备资源

同一套母本规则服务于 Chroma 与 S100，具体 CP、LAB / Production 目标以产品配置和生成器支持范围为准。当前 PCD009 的 S100 完整程序目标仅支持 LAB，不能据此推定任意平台组合都已开放。

输出范围当前内容适用工作
完整程序平台主程序与配套资源；Chroma 为 PLN 等文件，S100 为 PRG / PRJ 等文件。完整测试流程审阅与后续平台验证准备。
目标 Pattern当前程序目标实际引用的 Pattern，不输出主程序或 Pin 定义。按实际目标整理配套向量。
Pin 资源Chroma Pin DEC；S100 引脚、继电器与引脚组 PRJ 片段。先行准备平台引脚配置。
普通 FBIST普通 FBIST 共享资源，独立于 PUMP 汇总和 Flash 资源。先验证对应 Pattern 配置。
Flash 擦写 / 比较按 NM_pattern 配置整组生成 Flash 操作资源。集中准备擦除、编程与比较向量。
Flash 页 / UID按 ADDR_MAP 生成默认页映像、动态标签和已有 UID 变体资源。准备页面与 UID 相关数据载体。
PUMP 汇总按 FLOW 中 PUMP=yes 的配置生成 set_all_final_vposp 资源。汇总相关动态 DAC 字段和标签。

五种独立资源入口按各自必要配置检查，便于在整本测试流程尚未完成时分阶段准备资源；通过某一资源检查仅授权该范围。运行时 Trim / UID 数据仍需完整程序填入，资源执行仍依赖匹配的引脚、时序与外部输入。

04 / 工程优势

价值来自规则复用、可见性与可追溯性

同源配置，减少重复维护

双平台共用产品配置与测试语义，再由各平台生成对应代码。修改测试规则后，可在相同配置基础上审阅两边输出，减少分别手工维护时出现的偏差。

可视化编排，便于传递测试意图

Recipe 模块、字段说明和实际代码并排呈现，让配置评审能够围绕“执行什么、参数是什么、代码如何变化”展开，也为新人理解既有测试提供入口。

问题前移，缩短发现与修正路径

字段检查、关联定位和生成前预览把部分问题暴露在准备阶段。改值后明确标记待复查，避免把旧检查结果误当成当前配置已通过。

过程留痕，方便复查与交接

另存副本保留原母本；完整生成保留输入快照、SHA 和 manifest 文件清单。评审时能够追查这份输出来自哪份配置，而不依赖文件名猜测。

预期收益：减少重复编码与资源整理，提高双平台配置一致性，让测试程序的修改过程更容易审阅和交接。当前尚无统一工时基线与现场统计，因此不宣称具体效率提升百分比或缺陷下降比例。
