FLOW 新增测试项

字段关联核查与实施方案 · 2026-09-11 · V1.4

修订结论：以现有 typed kind 为字段规则主入口，不建立独立“测试类别”分类。由 CP / ITEM / TYPE 起步，补齐分类所需 mode、FV/FI 或 Recipe，再调用生产分类函数。下文“类别”均指既有 typed kind 的用户可读名称。本文是设计建议，未实现新向导，未改变现有业务规则。

补充核查：typed kind 到字段的实际代码关系

ProductCompiler 先补现有默认 Recipe，调用 compile_flow_rows 得到 FlowOperation.typed_kind，再调用各领域编译器，生成业务计划；program_plan 构造 TestDefinition，最终由 NATIVE_TYPED_KIND_REGISTRY 分派到平台程序组装。字段要求属于前面的领域编译阶段，不属于最后的组装注册表。

已有层实际职责与复用方式
flow_kinds.py复用 _classify_row / _classify_verify 现有分类关系；GUI 不另写一套 TYPE→类别分支。
preflight/schema.py → gui/workbook_editor.py已有 TYPED 格式／枚举及 CELL_CHOICES，GUI 已读取枚举。复用这些输入类型与选项，但 slash_ok 不代表特定 kind 可以缺省该字段。
core 各类型编译器已有必填、取值范围、条件、禁止字段和跨表资源检查。向导字段描述应按同一 kind 就近整理，并共用解析校验函数；不能把 required columns（表头存在）误当作每行必填。
typed_kind_registry.py / registered_typed_kinds.py注册 kind→组装函数，输入已经是 plans 和编译上下文；已检查的注册结构没有字段必填清单。不把表单元数据硬塞入平台组装注册表。

需要区分行分类与最终测试项分类

固件行先得到 VERIFY_HEX / VERIFY_KEIL，firmware_test.py 按同 CP/item 的连续阶段汇总：仅下载→CODE_DOWNLOAD；仅运行→FIRMWARE_RUN_TEST；下载加运行→FIRMWARE_FUNCTION_TEST。program_plan.py 使用业务计划中的最终 kind。因此新增完整测试项可以包含多行阶段，不能将最终 registered_kinds 直接当作单行 FLOW.type 下拉或假定分类双向一一对应。

字段状态不止必填／隐藏

应区分必填、条件填写、可推导、不适用／必须清空、以及来自其他表。例如 OPA_TEST 明确要求 FLOW 的 FV/FI、meas pin、low、target、high 为空或 /，测量数据来自 OPA；DAC_TEST 同样拒绝 FV/FI、meas pin、low、high，但要求 FLOW.target 和 Vcc。切换 kind 时不能只隐藏原值，提交应遵循该 kind 的空值规则。

建议接口只是现有 typed kind 的只读字段描述：返回当前 kind（或尚缺的分类输入）、各字段状态及依据、资源缺项。它不是新的分类器、生成器或通用规则引擎；完整检查继续使用 ProductCompiler。短期保留现有校验函数，能共享的原子检查直接复用；无法直接复用的描述用定向一致性检查约束，不能宣称仅凭注册表即可自动推导全部必填条件。

运行证据：使用现有 Python 环境直接调用 compile_flow_rows，10 个最小输入分别得到 STANDARD_TRIM、STANDARD_VERIFY、PDR_TRIM、OPA_TEST、DAC_TEST、ADC_TEST、PVD_TEST、FREQ_TEST、VERIFY_HEX、VERIFY_KEIL；另调用 _compile_search 验证 4 bit 完整码域为 0…15 且切换 LINE 不改变计划，以及 5 bit Pattern 下显式码 16,17 可被 4 bit 搜索配置接受。共 12 项定向关系检查通过；未修改工作簿，不代表所有 kind 组合或新 GUI 已验收。

新增证据：typed_kind_registry.py、registered_typed_kinds.py、compiler.py、program_plan.py、preflight/schema.py、workbook_editor.py。

1. 已核实的关键规则

问题代码事实向导建议
仅 TYPE 能否决定所有字段？不能。verify 还按 mode、FV/FI、Recipe 和特殊 item 分类；普通 trim 与 PDR/BOR 也走不同入口。TYPE 后补“执行方式／测试类别”；类别是界面概念，落盘仍使用现有列。
普通 TRIM 的 DAC bit必须为正整数，且不能大于所选 trim dac 的动态字段位宽。动态字段必须唯一。选完 Pattern 显示字段宽度及允许范围；可建议同宽，但不能未经确认假定搜索位数必须等于字段位宽。
Bisection普通 TRIM 接受 yes、no、both、both_m；依次是二分、全码扫描、两者启用、两者生成但只启用二分。用中文选项显示，写回原枚举。不能把空值视作有效选择。
step / LINE普通 TrimSpec 根据 step 是否为空或 / 决定完整码域或自定义码序；该函数不读取 LINE。旧平台 writers 仍有 LINE 分支。以“完整码域／自定义码序”单一控件联动：完整码域写 LINE=yes、step=/；自定义写 LINE=no 和明确码序。不要让用户分别填写容易矛盾的两列；不因此删除旧 LINE。
自定义码序校验支持整数、逗号或换行及起止范围；拒绝重复码；码值按 Pattern 字段宽度检查。完整码域为 0…2^DACbit−1。即时显示展开后的点数与范围；复用后端解析，不能简单把 step 当作步长，也不能擅自收紧为所有显式码必须小于 2^DACbit。
非 TRIM 是否不需要 step？不成立。ADC、DAC、OPA、PVD、固件及 SHMOO 路径也读取 step，分别用于执行模板、动作或扫描码；FREQ 当前要求空或 /，T 仅兼容旧配置。同一 Excel 列在不同分支显示不同名称与编辑器。普通 FBIST VERIFY 不展示 TRIM 搜索参数。
TRIM / VERIFY 都选同一种 Pattern？普通 TRIM 的 ENTER 与 TRIM 对应进入模式和写 DAC；普通 FBIST VERIFY 要有 ENTER、JUDGE，可有其他 Recipe 模块。keil/swd 等不是同一配置路径。按用途逐一选择，不能用一个 Pattern 下拉替代整个流程。功能型 VERIFY 转专用资源配置。
OTP / UID=yes影响后续结果消费。默认 COMMIT 读取同 CP 前面的 TRIM / VERIFY 标志；UID 目标过滤 uid 页。显式 OTP 映射路径存在跨页规则，不能简单强制“OTP 排除 uid 页”。要求选择或确认有效映射，并展示后续消费者。选完 ADDR_MAP 不代表已经完成烧写流程。
VERIFY 存储当前 GUI 存储入口要求可持久化的 RESULT EXPORT：BCD16_MV 或 ADC12_3V3。RAW 不能直接通过此入口映射。OTP/UID=yes 后先选输出来源和编码，再选字段；显示至少 16 / 12 bit 的宽度要求。不要替用户猜编码。
PUMP=yes聚合器按 FLOW item 查动态 trim dac / pump dac 行；TRIM 使用检查还要求后续同 CP SETVPOSP。Memory_Wakeup 的 PUMP 绑定不能用空存储映射绕过。增加 PUMP 资源、存储和消费者检查。仅绑定别名 TRIM Pattern 未必满足按 item 查找的 PUMP 聚合，必须明确提示。
OTP/UID/PUMP 全为 no不等于缺失映射自然合法；当前 CP1 Memory_Wakeup 对未显式排除的 TRIM 仍尝试建立字段映像。非 PUMP 可显式设置空存储绑定。提供“仅保留运行时结果，不存储”的明确选择；已有同名项全局映射时展示影响，不能静默清除。

2. 建议填写顺序

① 基础身份② 执行与 Pattern③ OTP / UID / PUMP④ 测试参数⑤ 位置与检查

① 基础身份

选择 CP、填写 ITEM、选择 TYPE。默认 CP 取当前分区；新逻辑名称与已有同名项区分。相同 CP 内的 item/type 子行必须连续，不能把新增子步骤误作独立测试项。切换 TYPE 时保留向导内旧分支输入供返回恢复，但提交仅输出当前有效分支。

② 执行与 Pattern

普通 TRIM 明确 mode=fbist，复用 ENTER → TRIM → JUDGE 模板，按用途选择进入模式与写 DAC。RUN、DEPEND 作为可选高级步骤保留真实顺序。普通 FBIST VERIFY 配置进入验证模式与测量判定，不要求填写搜索 DAC bit。其他 VERIFY 根据 ADC / DAC / OPA / PVD / FREQ / 通用固件类别展示对应配置表和资源，不强制套普通 TRIM 的 Pattern 选择器。

③ OTP / UID / PUMP

三个开关分开选择，默认 no 可作为建议，但应在总览中明确展示。OTP 或 UID 为 yes 时显示 ADDR_MAP 选择；VERIFY 先补结果输出格式。映射候选显示页、寄存器、字段、位段、宽度、适用 CP、占用者；不适合项保留原因说明。已存在同名逻辑项时沿用并展示全局绑定，修改需显示影响到的其他 CP。

PUMP 开启后检查动态资源与 SETVPOSP。三个开关均关闭时，显示是否仅保留运行时结果；不默默把缺失映射当成明确不存储。

④ 按分支填写测试参数

分支展示内容
普通 TRIMDAC bit、搜索方式、完整／自定义码序；UNIT、target、上下限、meas pin、FV/FI、Vcc；按需 PE、relay、Hbin/Sbin、sub。
普通 FBIST VERIFY测量／判定、供电、引脚、限值；需要时显示 PE、结果导出和 Recipe 高级步骤。若 target/限值来自 VERSION，显示真实来源，避免要求填写无效覆盖值。
ADC / DAC / OPA / PVD / FREQ对应专表条目和该类型的 step 模板、引脚、供电；例：PVD 要求两个不同测量引脚，DAC/OPA 的资源与普通 TRIM 不同。
PDR / BOR、SHMOO、存储和控制类型使用专用模板和规则，不宣称普通向导已覆盖。PDR 已核实要求 Bisection=yes、DAC bit=4，并依赖 VERSION 电压范围。其他类别逐项接入已验证路径。

“需要展示／建议用户填写”与“当前编译器明确必填”必须区分：所有硬性拒绝取自对应编译器；没有可靠默认来源的电压、目标、限值和引脚不得自动猜填。高级栏保持原表入口。

⑤ 插入位置、总览与检查

显示所属 CP、放在何项前／后，以及结果将由哪个后续 BUILDMAP / COMMIT / SETVPOSP 使用。默认建议当前 CP 中合法位置，不能盲目追加到 CP 末尾：它可能已经越过消费节点。确认后一次性创建行、Recipe 和映射草稿，一次撤销全部回退。

“加入草稿”与“整本检查通过”分开。允许暂存尚未完善的向导，明确列出缺项；完整检查通过才沿用现有导出／生成门禁。取消向导不遗留空行、半成品映射或用户未确认的 Recipe。

3. 一个普通 TRIM 示例

新建 CP1 / VREF_NEW / trim → 选择进入模式与一个 5 bit 动态 DAC Pattern → OTP=yes、UID=no、PUMP=no → 选择适用存储字段 → DAC bit=5、二分搜索、完整码域 → 界面展示 0…31，联动 LINE=yes / step=/ → 用户填写实际测量目标、限值、单位、引脚和供电 → 建议插在相关后续写入节点之前 → 总览确认后加入草稿并检查。

5 bit 只是示例，不能直接作为产品实际参数。存储字段要求按生产映射校验：当前 TRIM 的所需宽度取搜索位宽与动态字段宽度的较大值，并非只看 DAC bit。

4. 实现边界与工作量判断

界面复用较容易，完整字段依赖向导属于中等偏高复杂度。主要难点是未完成行也要能选候选、VERIFY 多分支、全局存储与同 CP 执行顺序，以及同列多种语义。

  1. 在现有 GUI 草稿边界增加局部向导状态；复用行新增、排序、撤销、Recipe 序列化与映射存储，不新增另一套工作簿格式。
  2. 后端提供小范围字段描述与候选查询：返回适用／必填／可推导字段、来源、候选和缺项。复用实际生产解析与校验函数；避免前端复制整套业务规则。字段“适用性说明”可配置，但不替代编译校验。
  3. 现有 trim_pattern 入口明确拒绝非 trim，须扩展普通 VERIFY 用途投影；不能只改弹窗标题就宣称 VERIFY 映射完成。
  4. 现有 storage_mapping 仍先整本编译，只有特定缺失 TRIM 存储错误的临时回退。拆出只读候选查询和局部校验，最终提交再完整编译，才能支持先映射后填测量参数。
  5. 首个完整交付建议覆盖普通 FBIST TRIM 与普通 FBIST VERIFY（含存储／不存储和错误引导），随后按已验证专用类型扩展。所有 TYPE 可见，但未覆盖者明确转专用配置，不能静默当普通项创建成功。

5. 验收条件

  • 普通 TRIM 完整码域和自定义码序均能创建、检查、另存重开；无错误 LINE/step 组合。
  • 不兼容位宽、无效 Pattern、重复码、缺失资源准确定位到向导步骤。
  • 普通 VERIFY 不要求 TRIM 搜索参数；带存储的 VERIFY 先完成 EXPORT 编码。
  • OTP / UID 标志、物理绑定与后续消费一致；PUMP 无动态资源／无后续 SETVPOSP 必须报告。
  • 已有同名项跨 CP 绑定不被静默覆盖；插入不会拆开已有测试组或越过依赖。
  • 取消零改动，创建一次撤销，切换类型不提交旧分支残留；未检查草稿不启用正式生成。
  • 定向前后端行为验证、真实窗口全流程和另存重开验证；不以 DOM stub 代替视觉验收。
